## Contracts and implementation

Public seams: `FCombatBattle::Restore(snapshot,error)`, `FExpeditionRun::Restore(snapshot,error)` and `NewRun(seed,error,optionalIdentity)`; `FExpeditionSave::{Encode,Decode,Write,Read,Ending,DefaultPath}` with reflected version-1 `FExpeditionSaveData`; `FExpeditionSession` owns the player's run and provides commands, Save, Resume and ReadRecords. Const queries remain the only run access. Restore constructs and validates candidates without Start/NewRun, generation or rolls. Missing/empty/null/wrong-type nested fields, fractional/overflow integers and invalid enums cannot hydrate defaults.

Every accepted command and whole enemy turn writes a candidate checkpoint before installation, including RNG and any deaths/outcome. Failure rejects that command and leaves both live state and prior file before the command. No stale backup fallback exists. Ending and current checkpoint share one file replacement; GUID run identities distinguish fresh same-seed expeditions, while explicit fixture identities keep deterministic tests possible. Historical records never enter power calculations. A sibling `.pending` write followed by the pinned Apple platform's POSIX rename preserves the previous checkpoint on write/rename failure. No fsync/power-loss, cloud, multiwriter or cross-version guarantee is claimed. Architecture and player rules document the contract.

Default path: `FPaths::ProjectSavedDir()/SaveGames/Expedition/current-v1.json`. Validation supports `-ExpeditionSaveRoot` or `EXPEDITION_SAVE_ROOT` to select owned ignored fixtures. Boot is read-only; N chooses fresh, F9 resumes, F5 confirms save, H inspects records. Resume rebuilds board/obstacles/markers and resets selection/preview/camera, with AI sequential on the game thread. A failed enemy checkpoint pauses presentation until successful Save/Resume.
