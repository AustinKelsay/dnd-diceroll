# Architecture conventions

Use C++ for stable foundations, reusable logic, integration, and behavior that benefits from native debugging or performance. Blueprint children can configure C++ parents and implement presentation and appropriate event behavior. Choose the boundary for the feature; avoid a C++-only rule. Keep related code cohesive inside the existing runtime module until a real dependency or loading boundary justifies another Unreal module. [Epic: C++ and Blueprint](https://dev.epicgames.com/documentation/unreal-engine/coding-in-unreal-engine-blueprint-vs-cplusplus)

For persistent strong references to reflected UObject members, use `UPROPERTY()` with `TObjectPtr<T>`. An unreflected `TObjectPtr` alone does not protect lifetime. Use `TWeakObjectPtr` for non-owning references that may expire, and `TSoftObjectPtr` for asset references that should support deferred loading. Raw pointers remain appropriate for short-lived locals and parameters when lifetime is established; validate references at use boundaries. [Epic: object pointers](https://dev.epicgames.com/documentation/en-us/unreal-engine/object-pointers-in-unreal-engine)

Expose purposeful tuning and configuration properties with suitable edit permissions, categories, tooltips, units, and editor ranges. Prefer limited access such as `EditDefaultsOnly` or `BlueprintReadOnly` where appropriate. Enforce invariants in runtime code too: metadata clamps only guide the editor and are not runtime validation. [Epic: metadata specifiers](https://dev.epicgames.com/documentation/en-us/unreal-engine/metadata-specifiers-in-unreal-engine)

Choose delegate features separately. Native versus dynamic concerns reflection, Blueprint access, serialization, and overhead; single-cast versus multicast concerns listener count. Multiple listeners alone do not require a dynamic delegate. Specify subscription ownership and unbinding when adding listeners, and avoid a global event bus without concrete requirements. [Epic: delegates](https://dev.epicgames.com/documentation/en-us/unreal-engine/delegates-and-lambda-functions-in-unreal-engine)

The boilerplate supplies infrastructure and a sandbox fixture. Add controllers, UI, navigation, networking, materials, or gameplay frameworks when an approved slice needs them. Do not rename internal Unreal identifiers as part of routine feature work; module/package renames require a separate migration.

## Expedition persistence

`FCombatBattle::Restore` and `FExpeditionRun::Restore` validate detached values before installing them. Restore never calls Start/NewRun, generates offers, rolls initiative or spends RNG. Combat validation checks bounded stats, grid/occupancy, life/HP/deadline consistency, enum values, initiative/order/active actor and budgets. Run validation checks the fixed roster and recipe facts, phase/completion/history/offer relationships, one camp, artifact state and reward-derived equipment/consumable allowances. This is coherent bounded-state validation, not a replay proof or tamper-proof format.

`FExpeditionSave` encodes version 1 value-only JSON with required fields and exact types, then validates the complete document. `FExpeditionSession` owns the live run for the player adapter. Every accepted party command, whole enemy turn, route, reward, recovery and new run is evaluated on a candidate. The candidate and any deduplicated ending record are written together before installation. A write failure rejects the candidate, including its random progression and deaths. Save is an explicit confirmation of this same checkpoint; Resume reads the latest committed file. There is no stale backup fallback. Presentation only submits session commands and observes const run queries.

The Mac local file adapter writes a sibling `.pending` file and uses the pinned Apple platform's same-directory POSIX rename to replace the destination. A failed write/rename preserves the prior valid checkpoint and history. The adapter does not promise fsync/power-loss durability, cloud sync, multiple writers or migration across save versions/platforms. A stale live session is rejected if its current value differs from the disk checkpoint. Startup does not write a run. Records contain identity, seed, outcome, victories and survivors/summary; they never enter party construction or power calculations.

Fresh runs use one GUID at construction. The seed remains the reproducible gameplay input; tests can supply an explicit run identity. Loading retains that identity. Default storage is `FPaths::ProjectSavedDir()/SaveGames/Expedition/current-v1.json`; native validation can select an isolated directory through `-ExpeditionSaveRoot=<directory>` or `EXPEDITION_SAVE_ROOT`. No reflected UObject or presentation selection/camera value enters a save.

The verified sandboxed Mac Development app resolves that default under `~/Library/Containers/com.YourCompany.DnDDiceRoll/Data/Library/Application Support/Epic/DnDDiceRoll/Saved/`. An override outside the app's sandbox can be unreadable even when the host can read it; native fixtures must use an owned directory the app can access. The editor's default remains the project's `Saved/` directory.
